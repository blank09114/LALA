# LALA (Learning And Learning Again)

---

## 프로젝트 개요

LALA는 사용자가 강의를 수강하고, 지식 제공자로 참여해 직접 강의를 개설할 수 있는 E-러닝 웹 애플리케이션입니다. 강의 수강 이후 수강평과 커뮤니티 활동으로 이어지는 학습 환경을 목표로 개발했습니다.

- 개발 형태: Spring Boot 기반 웹 애플리케이션
- 개발 인원: 6인
- 개발 기간: 2025.05.30 ~ 2025.07.10
- 담당 역할: 메인 페이지, 강의 목록·상세 페이지, LMS 화면의 프론트엔드 구현 및 API 연동

## 구조 및 설계

### 전체 구조

Spring Boot 기반의 MVC 구조로 구성했습니다. 웹 Controller는 Thymeleaf 템플릿과 초기 화면 데이터를 전달하고, REST API Controller는 화면에서 필요한 데이터를 JSON으로 반환하도록 구성했습니다.

메인 페이지의 사용자 정보와 관심 분야 강의는 Model에 담아 서버에서 렌더링했습니다. 학습 일정 조회, 강의 필터링, 상세 정보 조회와 같은 화면 내 데이터 갱신은 JavaScript의 Fetch API로 처리했습니다.

데이터 접근에는 MyBatis와 Spring Data JPA를 함께 사용했습니다. 강의·LMS·커뮤니티 기능은 Service와 MyBatis Mapper, XML SQL을 통해 처리하고, 회원 및 권한 관련 데이터에는 JPA Entity와 Repository를 사용했습니다.

### 학습 콘텐츠 구성

팀 전체 데이터 구조에서는 강의, 목차, 개별 학습 콘텐츠를 구분했습니다. 학습 자료는 영상·퀴즈·첨부파일 유형으로 나누고, 사용자별 학습 진도와 제출 이력은 별도 데이터로 관리했습니다.

프론트엔드에서는 콘텐츠 유형에 따라 영상 플레이어, 퀴즈 풀이, 파일 미리보기 화면을 제공했습니다. 각 화면에는 공통 목차와 질문 영역을 배치했습니다.

### 공통 UI 구성

헤더·푸터·강의 목록과 LMS의 반복 영역은 Thymeleaf fragment로 구성했습니다. 특히 학습 화면의 목차는 `lmsMenu`, 지식 제공자 코멘트와 질문 영역은 `lectureBottom`으로 분리해 영상·퀴즈·자료 화면에서 재사용했습니다.

인증에는 Spring Security의 폼 로그인과 OAuth2 로그인을 사용했으며, 관리자 화면 경로에는 관리자 Role을 확인하는 접근 규칙을 적용했습니다.

## 주요 기능

다음은 팀 프로젝트 전체의 주요 기능입니다.

- 강의 탐색: 카테고리·가격·난이도 필터와 키워드 검색
- 강의 상세: 소개, 목차, 수강평, 찜 및 장바구니
- LMS: 영상 시청, 퀴즈 제출, 학습 자료 열람 및 다운로드
- 강의 개설: 지식 제공자의 강의·목차·학습 자료 등록
- 학습 관리: 수강 강의, 진도율, 학습 일정 및 주간 목표 조회
- 커뮤니티: 게시글·댓글 작성 및 관리, 좋아요와 신고
- 관리자: 회원·강의·게시글 조회 및 상태 관리

## 구현

메인 페이지, 강의 목록·상세 페이지와 LMS 화면의 프론트엔드 구현을 담당했습니다. Thymeleaf 템플릿을 적용하고, 팀에서 구현한 백엔드 API를 연결해 데이터를 표시하고 사용자 동작에 따라 화면 상태를 변경했습니다.

### 메인 페이지

사용자 닉네임과 프로필, 관심 분야에 해당하는 강의를 Thymeleaf로 표시했습니다. 프로필 이미지가 없는 경우 기본 이미지를 출력하고, 추천 강의는 공통 목록 fragment를 사용해 구성했습니다.

학습 일정과 주간 목표, 최근 수강 정보는 메인 데이터 API에서 비동기로 조회했습니다. 응답 데이터를 바탕으로 날짜별 일정과 목표 목록을 만들고, 최근 강의의 제목·진도율·진행 막대를 갱신했습니다.

일정이나 목표가 없는 경우 안내 문구를 표시했으며, 최근 수강 강의가 없으면 해당 영역을 숨기도록 처리했습니다.

### 강의 목록과 탐색 UI

카테고리·가격·난이도 선택값을 `filterState` 객체로 관리했습니다. 사용자가 필터를 변경하면 API에 조건을 전달하고, 응답받은 강의 목록으로 화면을 다시 구성했습니다. 선택한 항목에는 별도 클래스를 적용해 현재 필터 상태를 표시했습니다.

키워드 검색은 URL의 `keyword` 파라미터를 읽어 검색 API와 연결했습니다. 검색 초기화 시에는 검색어를 제거하고 목록을 다시 조회하도록 구성했습니다.

강의 카드는 `DocumentFragment`를 사용해 네 개씩 행으로 묶었습니다. 썸네일, 제목, 강사명, 가격, 평점과 난이도를 표시하고, 할인 강의는 원가·할인율·할인가를 구분했습니다.

지식 제공자 목록은 가로 스크롤 영역으로 구성했습니다. 좌우 버튼으로 부드럽게 이동하고, 스크롤 위치에 따라 이동 버튼의 노출 상태를 변경했습니다.

### 강의 상세와 사용자 인터랙션

강의 상세 API의 응답을 강의 정보·목차·수강평 영역으로 나누어 렌더링했습니다. 목차는 챕터별 API를 연결해 영상·퀴즈·첨부자료 항목을 구성하고, 개별 또는 전체 목차를 접고 펼칠 수 있도록 구현했습니다.

수강평은 별점과 내용 입력을 검사한 뒤 등록 API로 전달했습니다. 본인이 작성한 수강평에는 수정·삭제 버튼을 표시하고, 수정 폼 전환과 삭제 확인 모달을 연결했습니다. 조회한 수강평은 최신순·평점순으로 정렬하고, 다섯 개씩 추가로 표시하도록 구성했습니다.

장바구니는 공용 모듈과 연결했습니다. 강의 정보를 브라우저의 `localStorage`에 저장하고, 이미 담긴 강의는 버튼 문구를 변경하고 비활성화했습니다. 찜 기능은 등록·해제 API의 응답에 따라 아이콘 상태를 변경했습니다.

사용자 동작의 결과는 토스트로 안내했으며, 강의 URL 복사와 소개·목차·수강평 영역으로 이동하는 스크롤 기능을 구현했습니다.

### LMS 홈과 공통 학습 UI

LMS 홈에는 강의 기본 정보와 조회된 진도율, 목차를 표시했습니다. 목차를 펼치면 해당 챕터의 자료를 비동기로 불러오고, 콘텐츠 유형에 따라 학습 화면으로 이동하도록 구성했습니다.

수강생과 지식 제공자에 따라 액션 영역을 구분하고, 목차가 없거나 자료를 불러오지 못한 경우 안내 문구를 표시했습니다.

영상·퀴즈·파일 화면에서 반복되는 목차와 질문 영역은 Thymeleaf fragment로 분리했습니다. 목차 렌더링과 질문 조회·등록은 공통 JavaScript 모듈로 구성해 여러 학습 화면에서 재사용했습니다. 질문 목록에서는 서버가 반환한 기존 답변도 함께 표시했습니다.

### 영상 플레이어

HTML5 `<video>` API를 사용해 학습용 영상 플레이어를 구현했습니다. 영상 상세 API에서 받은 주소를 재생 요소에 연결하고, 재생·일시정지, 재생 위치 이동, 배속 변경과 전체 화면 전환을 제어했습니다.

재생 시간과 진행 막대를 영상 상태에 맞춰 표시하고, 진행 막대의 클릭·드래그로 재생 위치를 변경할 수 있도록 구성했습니다.

### 퀴즈와 첨부자료 화면

퀴즈는 문항 유형에 따라 객관식 라디오 버튼과 주관식 텍스트 입력을 표시했습니다. API에서 제출 이력을 조회해 기존 답안을 복원하고, 제출된 답안이 있는 경우 입력 영역을 비활성화하도록 구성했습니다.

답안은 제출 API로 전달했으며, 조회한 답안과 정답을 브라우저에서 비교해 결과를 표시했습니다.

첨부자료는 파일 형식에 따라 화면을 구분했습니다. PDF는 `iframe`으로 미리보기를 제공하고, 그 외 형식은 파일명·확장자와 다운로드 링크를 표시했습니다.

## 기술적 고민 및 개선점

### API 명세와 화면 상태의 일치

프론트엔드와 백엔드를 연결하는 과정에서 응답 데이터의 구조가 UI 요구사항과 어긋나 수정하는 경우가 있었습니다. 이를 통해 화면에 필요한 데이터와 상태를 API 설계 단계에서 함께 정의해야 한다는 점을 배웠습니다.

현재 코드에서도 검색과 필터 요청이 서로 다른 경로를 사용하고, 목록 페이지 이동 연결이 미완성인 부분이 남아 있습니다. 이후에는 검색·필터·페이지 이동에 필요한 요청 조건과 응답 형식을 먼저 합의하고, 실제 화면 흐름을 기준으로 연동을 점검하고자 합니다.

### 비동기 요청 실패와 사용자 피드백

토스트와 모달로 일부 동작의 결과를 안내했지만, 요청 실패를 콘솔에만 출력하는 부분도 남아 있습니다. 퀴즈 제출처럼 요청 전에 입력을 비활성화하는 화면은 실패 이후 다시 시도할 수 있도록 상태를 복구할 필요가 있습니다.

후속 개선에서는 로딩·성공·실패 상태를 구분하고, 실패 원인 안내와 입력 상태 복구를 함께 처리하고자 합니다.

### 화면 크기 대응과 스타일 중복

일부 화면에는 미디어쿼리를 적용했지만, 강의 상세와 LMS 공통 레이아웃에는 고정 폭이 남아 있어 모바일 대응 범위가 충분하지 않았습니다. 페이지별 CSS 파일을 중심으로 작업하면서 공통 스타일이 중복되는 문제도 있었습니다.

이후에는 공통 레이아웃과 반복되는 UI 스타일을 정리하고, 좁은 화면에서 목차와 학습 콘텐츠가 자연스럽게 재배치되도록 개선하고자 합니다.
